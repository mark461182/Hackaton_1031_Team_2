# 03 MVP 스펙

**원칙: 하나의 흐름이 처음부터 끝까지 진짜로 돌아간다.** 기능 개수보다 심사위원이 직접 해 봤을 때 결과가 나오는 게 중요하다 (구현 40점).

## 만드는 것 / 안 만드는 것

03:00 기능 동결 전에 어디까지 진짜로 돌릴지다 (11/1 결정 시트). 심사위원이 직접 넣어 보는 건 "꼭 동작" 줄이다. 누가 무엇부터 만드는지는 [09 역할별 작업](09_역할별_작업.md).

| 수준 | 기능 |
| --- | --- |
| **꼭 동작** | 아이 ↔ 코끼리 **음성** 대화 + 글자 입력 (아래 "음성" 참고) · 대화 분류 (일상 / 공유 제안 / 위험) · 부모 질문 → 코끼리가 다듬기 (원래 질문·코끼리 버전 나란히) → 대화 도중 자연스럽게 질문 → 아이 답 자동 전송 (답장 카드) · 위험 신호 → 부모 알림 + 대화 가이드 · 두 폰 데모 모드 (데스크톱에서 부모·아이 화면 나란히) · "예시 가족으로 체험하기" · 코인 쌓기 (대화 마침. 사진 코인은 사진 올리기가 될 때) |
| **되면 동작** | 공유 제안 → 아이 동의 → 부모 전달 · 대화 마침 → 오늘 대화로 3줄 일기 → 달력 (대화 = 파란 점, 사진 = 빨간 점) · 일상 사진 올리기 |
| **정적 화면** (예시 데이터, 실제 처리 없음) | 기프티콘 교환 · 주간 리포트 + 다음 주 질문 추천 · 가족 스토리북 미리보기 + 주문 (가짜 결제) · 부모 코인 충전 |
| **발표 장표로만** | 학교·교육청 연결 · 광고 (추후 검토) · 코끼리 꾸미기 |
| **안 만든다** | 실제 결제·충전·기프티콘 발송 · 회원가입·이메일 인증 · 푸시 알림 (화면 안 알림으로 대체) · 사진 편집 · 기분 날씨 체크인 · 생활 미션 (집안일) |

## 핵심 흐름

(11/1 결정 시트 반영. 대사는 예시이고 실제 말은 챗봇 담당이 정한다)

```
[아이] 코끼리와 대화 → [서버] 메시지마다 LLM 분류
  ├ 일상: 저장. 답장 카드·알림은 없음 (3줄 일기에는 들어감)
  ├ 공유 제안: 코끼리가 엄마한테 같이 말할지 물음 (아이 화면 금지 문구의 유일한 예외)
  │    → 아이 [좋아] → 부모에게 / [싫어] → 안 감 (일기에서도 뺌)
  └ 위험 신호: 코끼리가 공감하고 혼자 참지 않게 권함 (전달된다고 말하지 않음)
       ├ 가족이 당사자 → 부모 알림 없음. 코끼리는 다른 믿을 만한 어른에게 도움을 청하도록 권함
       └ 그 밖 → 부모에게 알림: 아이 말 원문 1~2문장 + 상황 요약 + 대화 가이드
  ※ 아이가 "말하지 마"라고 한 내용은 위험이 아니면 부모 쪽(답장 카드·일기·리포트·스토리북)에 쓰지 않는다
```

```
[부모] 걱정이나 질문 입력 (예: "준우가 요즘 친구 얘기를 안 해요")
   → LLM이 아이가 답하기 쉬운 질문으로 다듬음 (예: "요즘 같이 노는 친구 중에 제일 웃긴 친구는 누구야?")
   → 부모 화면에 원래 질문 / 코끼리 버전 나란히
   → 아이와 대화하던 코끼리가 몇 턴 안에 꼭 물음. 서버가 보장하고, 물었다는 신호로 askedAt을 남김
     (몇 번째 턴에 어떤 말로 이을지는 챗봇 담당. 부모 질문이라고 밝히지 않음. 대기 질문은 한 번에 하나)
   → 아이 답 + 꼬리 질문
   → 부모에게 자동 전송: 답장 카드 (아이 답 원문 + 코끼리 요약·메모). 아이는 전달 사실을 모름
     · 답이 위험이면 답장 카드 대신 위험 알림 하나
     · 아이가 "말하지 마"라고 한 내용은 위험이 아니면 빼고 보냄
```

```
[부모] 코인 충전 (정적 화면, 실제 결제 없음). 부모 충전액과 아이 코인은 따로 둔다
[아이] 대화를 마침 / 일상 사진을 올림 → 코인 +
   → 최소 기준과 횟수 제한을 둔다. 숫자는 대화 마치기를 만드는 사람이 정해 여기 적는다: (아직 없음)
   → 대화를 마치면 오늘 대화로 3줄 일기 → 달력 파란 점 ("말하지 마"·[싫어] 내용은 뺌)
   → /kid/coins 에서 모은 코인으로 기프티콘 고르기 (정적 화면, 가짜 교환)
   → 기프티콘 가격 = 상품가 + 수수료 (우리 수익)
```

## 음성 (아이 화면의 기본 입출력)

금쪽이 코끼리처럼 **말로 묻고 말로 답하는 것**이 핵심 경험이다. 글자 입력·선택지 버튼은 대체 수단으로 항상 남긴다.

| 항목 | 1차 (먼저 만든다) | 2차 (여유 있으면) |
| --- | --- | --- |
| 말 → 글자 (STT) | 브라우저 Web Speech API `SpeechRecognition`, `lang: 'ko-KR'` | 클라우드 STT |
| 글자 → 말 (TTS) | ~~브라우저 `speechSynthesis`~~ → 타입캐스트 아동 목소리 "하율" (`/api/tts`, 아래 표). 실패하면 브라우저 `speechSynthesis` | — |

**코드:** `src/lib/voice` (공용 모듈) · `/voice-lab` (실험 페이지)

```ts
import { createPushToTalk, pickTranscript, speak, unlockTts } from "@/lib/voice";

// 첫 버튼 onClick에서 한 번 (iPhone 무음 해제)
unlockTts();

// 꾹 누르고 말하기
const ptt = createPushToTalk((interim) => setLive(interim));
onPointerDown: ptt.start();
onPointerUp:   const alts = await ptt.stop();
               const text = pickTranscript(alts, 화면의_선택지들);   // 맥락 순위 + 선택지 맞추기

// 코끼리 답 읽기 (이모지·ㅋㅋ·괄호 정리 → 문장 단위로 읽음)
await speak(reply, { voiceURI, rate, pitch });   // 값은 /voice-lab에서 고른 것
```

**정확도 올리는 방법 (구현됨)**
| 대상 | 방법 |
| --- | --- |
| STT | 후보 5개 받기 → 초저 대화 단어(학교·짝꿍·급식…)로 다시 순위 → 화면 선택지와 비슷하면 그 선택지로 맞춤 → `/voice-lab`에서 글자 오류율(CER) 측정 (엔진 그대로 vs 보정 후) |
| TTS | 기기의 한국어 목소리 중 자연스러운 것 자동 선택, 이모지·ㅋㅋ·ㅠㅠ·괄호·말줄임표 정리, 문장 단위로 나눠 읽기 (크롬은 긴 문장을 읽다 끊김), 속도·높낮이 조절 |
| 다음 (Bedrock 붙인 뒤) | 후보 여러 개 + 직전 코끼리 질문을 LLM에 같이 넘겨 문맥으로 고르게 하기 |

**코끼리 목소리 = 타입캐스트 아동 목소리 "하율" (`/api/tts`)**
| 항목 | 동작 |
| --- | --- |
| 크레딧 | 읽은 글자 수만큼 차감 (≈ 1자 = 1크레딧), 무료 계정 15,000 · 동시 요청 계정당 2개 |
| 키 돌려 쓰기 | `TYPECAST_API_KEYS=키1,키2,…` — 요청마다 시작 키를 바꾸고, 크레딧 부족(402)·동시 초과(429)·키 오류면 다음 키로 |
| 길이 | **답 길이는 코끼리 프롬프트로 1~2문장.** 서버 300자는 안전장치일 뿐. 더 긴 답은 `speak()`가 문장 단위로 나눠 보내 끝까지 하율 목소리로 읽음 (자르지 않음, 다음 덩어리는 미리 받음) |
| 고정 대사 | `src/lib/voice/fixed.ts` 문장은 `public/voice/*.mp3`를 틀어 **크레딧 0·지연 0** (인사·작별·맞장구 12개). 추가: 목록에 넣고 `node scripts/gen-fixed-voice.mjs` |
| 기다리는 동안 | LLM 답을 기다릴 때 `speakFiller()` → "음~", "응응.", "잠깐만, 생각 좀 해 볼게." 중 하나 (중립적인 것만) |
| 개발 중 | `.env.local`에 `TTS_CLOUD=off` → 브라우저 목소리 (고정 대사는 그대로). **Vercel에는 넣지 않는다** |
| 대체 | 키가 다 떨어지거나 오류면 그 부분부터 브라우저 목소리로 이어 읽음 |
| 남은 크레딧 | `bash scripts/tts-credits.sh` |

**동작**
- **꾹 누르고 말하기** 버튼 (무전기 방식). 계속 듣다가 말 끝을 감지하는 방식은 쓰지 않는다
- 받아쓴 글자를 화면에 보여주고 [맞아] [다시 말하기] → 아이 발음 오인식 대비
- 코끼리가 답을 준비하는 동안 "음…" 생각하는 애니메이션. 답은 1~2문장, 글자가 먼저 뜨고 음성이 따라 나옴
- 화면 가득 코끼리 = 태블릿을 식탁에 세워 둔 "스피커 같은 화면"

**함정과 대응**
| 함정 | 대응 |
| --- | --- |
| 아이 목소리 인식률 낮음 | 받아쓴 글자 확인 + 선택지 버튼 유지 |
| iPhone 사파리는 사용자가 누르기 전 소리 재생 불가 | 첫 화면 [코끼리랑 이야기하기] 버튼으로 시작 |
| 브라우저 지원 차이 (크롬 O, 사파리 불안정, 파이어폭스 STT X) | 지원 안 되면 마이크 버튼 숨기고 글자 입력으로 자동 전환 |
| STT → LLM → TTS 지연 3~6초 | 생각 중 애니메이션, 짧은 답 |
| 해커톤 현장 소음 | 데모 영상은 조용한 곳에서 음성으로 촬영, 라이브 시연은 글자 입력 기본 |
| 마이크 권한은 HTTPS 필요 | Vercel 배포 주소에서 테스트 (localhost는 예외로 허용됨) |

**규칙**
- **녹음 파일은 저장하지 않는다.** 받아쓴 글자만 저장 (크롬 음성 인식은 소리를 구글 서버에서 처리함)
- 코끼리 목소리는 방송의 "하준" 목소리를 쓰지 않는다
- 음성 파일(녹음, TTS mp3)은 Supabase에 올리지 않는다. 고정 대사 mp3는 `public/voice/`, 그때그때 만든 TTS는 서버에 저장하지 않는다 (11/1)

## 데이터 구조 (초안)

실제 타입은 건준이 `src/lib/types.ts`에 먼저 만든다 ([09 역할별 작업](09_역할별_작업.md) 1장). 아래는 그 출발점이다.

```ts
Family   { id, name, coins }                 // 부모 충전액과 아이 코인은 따로 둔다 (11/1)
Message  { id, familyId, from: 'kid' | 'kokkiri', text, createdAt,
           category?: 'daily' | 'share' | 'risk', questionId? }
           // 아이가 "말하지 마"라고 한 내용, [싫어]한 공유는 부모 쪽에 쓰지 않도록 표시 (11/1)
Share    { id, familyId, messageId, summary, status: 'proposed' | 'accepted' | 'declined' }
Alert    { id, familyId, quote, situation, guide, createdAt, readAt? }
           // ~~원문 미포함~~ → quote = 아이 말 원문 1~2문장 (11/1). 가족이 당사자면 만들지 않음
Question { id, familyId, original, rewritten, askedAt?, answeredAt? }  // askedAt = 코끼리가 실제로 물은 때
Reply    { id, familyId, questionId, answer, summary, note, createdAt } // 답장 카드: 아이 답 원문 + 요약·메모
Entry    { id, familyId, date, type: 'chat' | 'photo', ref, diary? }  // 달력, diary = 3줄 일기 ("말하지 마"·[싫어] 제외)
CoinLog  { id, familyId, reason: 'chat_done' | 'photo', amount, createdAt }
Gift     { id, name, price, fee }                                    // 기프티콘 (가짜), fee = 우리 수수료
Report   { id, familyId, week, summary, nextQuestions }               // 주간 리포트 (정적 화면)
```

- 저장소: **Supabase** ([05 결정 기록](05_결정_기록.md), 11/1). 음성 파일은 올리지 않는다
- 심사위원끼리 섞이지 않게 방문자마다 예시 가족을 따로 만든다 (방법은 저장 담당)

## API (초안) — 건준. LLM·TTS만 하고 저장하지 않는다

필요한 맥락(대화 기록, 대기 중인 부모 질문)은 요청에 담아 받고 결과를 돌려준다. 부모에게 무엇이 가는지(분류, 답장 카드·알림·공유 내용)는 여기서 정한다. 요청·응답 모양은 `src/lib/types.ts`에 둔다. 키가 없어도 같은 모양의 가짜 응답을 낸다.

| 메서드 | 경로 | 하는 일 |
| --- | --- | --- |
| POST | `/api/kid/chat` | 아이 메시지 + 대화 기록 + 대기 질문 → 코끼리 답·선택지·분류 + (해당하면) 답장 카드·위험 알림·공유 제안 내용 + 물었다/답했다 신호 |
| POST | `/api/parent/ask` | 부모 질문 → 아이가 답하기 쉬운 말로 다듬은 버전 (원래·코끼리 버전) |
| POST | `/api/kid/done` | 오늘 대화 → 3줄 일기 ("말하지 마"·[싫어] 내용 제외) |
| POST | `/api/tts` | 글자 → 코끼리 목소리 (구현됨, 위 "음성") |
| GET | `/api/parent/report` | 주간 리포트 + 다음 주 질문 추천 (정적 화면이면 안 만들어도 됨) |

- LLM: **AWS Bedrock** (05, 11/1). 모델·키 이름은 건준이 `.env.example`에 적는다
- ~~데이터만 다루는 API (share·photo·gift·feed·book/order·calendar)~~ → 아래 저장 함수로 옮김 (11/1)

## 저장 함수 (초안) — 성준·재모. `src/lib/store.ts`

화면은 Supabase를 직접 부르지 않고 이 함수들만 부른다. API 결과를 저장하는 것도 화면이 이 함수로 한다. 함수 이름과 모양은 성준·재모가 정해 `types.ts`와 맞춘다.

## LLM 프롬프트 요구사항

> 아래 말투·응답 예시는 **예시**다. 실제 말투·대사·필드 이름은 챗봇 담당(건준)이 정한다 ([04 협업 규칙](04_협업_규칙.md) 2장). 꼭 지킬 것은 CLAUDE.md 절대 규칙과 아래 분류 기준이다.

**코끼리 말투**
- 초등 1~3학년이 읽을 수 있는 짧은 문장, 한 번에 질문 1개
- 평가·훈계·정답 제시 금지. 공감 → 열린 질문 ("그때 기분이 어땠어?")
- **유도 질문 금지:** "엄마 좋지?", "친구가 나빴지?"처럼 원하는 답을 정해 놓은 질문 X
- 음성으로 읽힐 문장이므로 이모지·괄호·영어 약어 X
- 유치한 아기 말투 금지 (도하 메모: 친근함을 늘리려고 유치하게 말하면 효과 없음)
- 부모 질문은 코끼리가 궁금한 것처럼 대화 흐름에 맞춰 묻는다. "엄마가 물어봤는데" 같은 말, 부모에게 전달된다는 말 X
- "비밀로 해 줄게", "너랑 나만 아는 비밀" 같은 약속 X
- 선택지 버튼을 같이 제시할 수 있게 JSON으로 응답

**부모 화면 말투 (코치)**
- 존댓말. 아이 답을 정리하고 이유와 팁을 같이 준다 ("친구 이름이 처음 나왔어요. 저녁에 '민준이는 오늘 뭐 했어?'로 이어 보세요")

**분류 기준**
- `risk`: 맞음·괴롭힘·따돌림·협박, 자해·죽고 싶다, 어른의 부적절한 접촉·비밀 강요, 낯선 사람, 학대 의심
- `share`: 부모가 알면 아이에게 도움이 되는데 아이가 망설이는 이야기 (서운함, 실수, 걱정)
- `daily`: 그 외
- 애매하면 `risk`로 올리지 말고 `share`로 → 오탐으로 아이 신뢰를 깨지 않는다
- ~~위험 알림은 상황 요약으로 쓴다~~ → 위험 알림은 아이 말 원문 1~2문장 + 상황 요약 + 대화 가이드 (11/1). 부모 질문의 답장 카드에는 아이 답 원문을 그대로 넣는다
- 부모 질문의 답이 위험이면 답장 카드를 따로 만들지 않고 위험 알림 하나로 보낸다
- 가족이 위험의 당사자면 부모 알림을 만들지 않는다. 그래서 분류할 때 누가 관련됐는지(친구·가족·낯선 사람)도 같이 낸다
- 아이가 "말하지 마"라고 한 내용과 [싫어]한 공유는 위험이 아니면 답장 카드·3줄 일기·리포트에 쓰지 않는다
- 대기 중인 부모 질문은 몇 턴 안에 꼭 묻고, 물었다는 신호를 응답에 남긴다 (몇 번째 턴인지는 챗봇 담당)

**응답 형식 (예시. 필드 이름은 챗봇 담당이 정함)**
```json
{ "reply": "많이 속상했겠다. 그 친구가 언제부터 그랬어?",
  "choices": ["어제부터", "꽤 오래됐어", "말하기 싫어"],
  "category": "risk",
  "parentSituation": "학교에서 친구 관계로 힘든 일이 있는 것 같아요",
  "parentGuide": "혼내지 않을 거라고 먼저 말해 주고, '요즘 짝꿍이랑은 어때?'로 시작해 보세요",
  "answeredQuestionId": null }
```

**부모 질문에 답했을 때 (예시)**
```json
{ "reply": "와, 민준이 진짜 웃기다. 둘이 쉬는 시간에 뭐 하고 놀아?",
  "choices": ["술래잡기", "그림 그리기", "그냥 얘기해"],
  "category": "daily",
  "answeredQuestionId": "q1",
  "parentSummary": "요즘 제일 웃긴 친구로 민준이를 꼽았어요. 쉬는 시간에 같이 노는 것 같아요",
  "parentNote": "친구 이름이 처음 나왔어요. 저녁에 '민준이는 오늘 뭐 했어?'로 이어 보세요" }
```

## 데모 체크 (심사위원 시점)

[꼭] = 03:00 전에 꼭, [되면] = 되면, [정적] = 정적 화면 ("만드는 것" 표)

- [ ] [꼭] 배포 URL 접속 → 설명 없이 "예시 가족으로 체험하기"를 누를 수 있다
- [ ] [꼭] 코끼리가 먼저 **소리로** 말을 건다 (첫 버튼 누른 뒤)
- [ ] [꼭] 꾹 누르고 말하기 → 받아쓴 글자 확인 → 코끼리가 소리로 답한다
- [ ] [꼭] 마이크가 안 되는 브라우저에서도 글자 입력으로 끝까지 쓸 수 있다
- [ ] [꼭] 두 폰 데모 모드에서 한 화면으로 아래 흐름을 다 볼 수 있다
- [ ] [꼭] 부모가 맡긴 질문이 원래·코끼리 버전 나란히 보이고, 아이로 서너 번 말하는 안에 코끼리가 자연스럽게 묻는다
- [ ] [꼭] 아이가 답하면 부모 화면에 답장 카드(아이 답 + 요약·메모)가 자동으로 뜬다. 아이 화면엔 "전달됐다"는 말이 없다
- [ ] [꼭] 아이로 "짝꿍이 맨날 때려" 입력 → 코끼리가 공감한다. 부모에게 알린다고 말하지 않는다
- [ ] [꼭] 부모 화면에 위험 알림(아이 말 1~2문장 + 상황 요약) + 가이드가 뜬다
- [ ] [꼭] 아이로 "아빠가 때려" 입력 → 부모 화면에 위험 알림이 뜨지 않는다
- [ ] [꼭] 아이로 "급식에 떡볶이 나왔어" → 답장 카드·알림으로는 안 뜬다 (3줄 일기에는 들어갈 수 있다)
- [ ] [꼭] 아이가 "엄마한테 말하지 마"라고 한 내용은 답장 카드에 안 나온다 (위험 제외)
- [ ] [꼭] 대화를 마치면 코인이 오르고, [끝내기]를 연타해도 기준 없이 오르지 않는다
- [ ] [되면] 대화를 마치면 3줄 일기가 생기고 달력에 점이 찍힌다. "말하지 마"·[싫어] 내용은 빠진다
- [ ] [되면] 공유 제안에 [좋아]면 부모에게 가고, [싫어]면 안 간다
- [ ] [되면] 사진을 올리면 코인이 오르고 달력에 빨간 점이 찍힌다
- [ ] [정적] 기프티콘을 고를 수 있고, 부모 충전 화면이 있다
- [ ] [정적] 주간 리포트에 다음 주 질문 추천이 나온다
- [ ] [정적] 스토리북 미리보기 → 주문(가짜 결제)까지 간다
- [ ] [꼭] 서로 다른 입력 → 서로 다른 결과 (고정 답변 아님)
