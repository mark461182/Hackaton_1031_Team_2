# 04 협업 규칙

24시간이다. 규칙은 **충돌 안 나게, 배포 안 깨지게** 두 가지만 지키면 된다. 팀이 개발 초보라 **코드를 쓰는 컴퓨터를 두 대로 줄였다** (11/1, [05 결정 기록](05_결정_기록.md)).

## 1. 역할

| 컴퓨터 | 담당 | 하는 일 |
| --- | --- | --- |
| 1 | 건준 | 코끼리 머리와 목소리: `/api/*`, 프롬프트·분류·말투, 부모 질문 다듬기, 음성(STT·TTS), `src/lib/types.ts`, 가짜 응답, AWS Bedrock |
| 2 | 성준·재모 (한 컴퓨터에 같이) | 나머지 앱 전부: 첫 화면·`/demo`·아이 화면·부모 화면(정적 화면 포함), Supabase 저장(`store.ts`), 예시 가족 데이터, 디자인 적용(색·글꼴·버튼·카드) |
| 없음 | 도하 | 코드는 고치지 않는다. 코끼리 그림, 디자인 가이드(색·글꼴·버튼 느낌), 서비스·코끼리 이름, 가격 숫자(출처 포함), 배포 주소 점검, 발표 자료·60초 영상·Q&A |
| | 다같이 | 05 결정 기록 덧붙이기, 08:00 제출 (README 제출물 체크) |

- 두 컴퓨터 사이의 약속은 [09 역할별 작업](09_역할별_작업.md) 1장, 역할별로 무엇부터 할지는 09 2~4장
- 부모에게 무엇이 가는지(분류, 답장 카드·알림 내용)는 API(건준)가 정한다. 화면은 그 결과를 저장하고 보여 준다
- 도하가 만든 그림과 디자인 가이드는 팀 채널로 넘기고, 성준·재모가 저장소에 넣는다

## 2. 누가 무엇을 정하나

문서(CLAUDE.md, 01, 03, 05)는 팀 공통 틀만 정한다: 아이에게 무엇을 알리고 부모에게 무엇이 가는지, 저장·API 구조, 범위, 역할. 그 안의 구체적인 것은 담당이 정한다. 문서 속 말투·대사·JSON·화면 예시는 예시일 뿐이다.

| 담당 | 정하는 것 |
| --- | --- |
| 건준 | 코끼리 말투·대사·대화 흐름, 부모 질문을 언제 어떤 말로 묻는지, 답장 카드에 담을 범위, 코치 메모, 프롬프트, 응답 필드 이름, Bedrock 모델 |
| 성준·재모 | 화면 배치·동작, 도하 가이드를 화면에 옮기는 방법(컴포넌트·CSS), 저장 구조(Supabase 테이블), 예시 가족 데이터 내용, 정적 화면 모양, 코인 기준 숫자(03 핵심 흐름에 적음) |
| 도하 | 코끼리 생김새·상태, 디자인 가이드(색·글꼴·버튼 느낌), 서비스·코끼리 이름, 가격 숫자, 발표 |

- 정한 것이 다른 사람 일에 걸리면(예: 응답 필드 이름) `types.ts`나 03에 적고 팀 채널에 알린다
- 틀(CLAUDE.md 절대 규칙, 05 확정)과 부딪히면 혼자 바꾸지 말고 팀 채널에서 정한 뒤 05에 덧붙인다

## 4. 브랜치 · 커밋 · PR

**초보용 세 줄**
1. 올리기 전에 `git pull`과 `npm run build`
2. 내 컴퓨터 몫 폴더만 고친다. `package.json`을 바꾸면 팀 채널에 한 줄
3. 30분마다 작게 올린다. 15분 넘게 막히면 팀 채널에 바로 말한다

- `main` = **항상 배포되는 상태.** Vercel이 main을 자동 배포한다
- 작업은 `이름/기능` 브랜치 → PR → 한 명이 훑어보고 머지 (예: `jaemo/kid-chat`)
- 커밋 메시지는 한국어 한 줄: `아이 대화 화면 선택지 버튼 추가`
- `.env.local`, API 키, 원본 수집 데이터는 **절대 커밋 금지**

**매번 하는 순서**
```bash
git switch main && git pull          # 최신 main 받기
git switch -c 이름/기능               # 새 브랜치
# … 내 컴퓨터 몫 폴더에서 작업 …
npm run build                        # 통과 확인 (빌드 깨지면 배포도 깨진다)
git add -A && git commit -m "아이 대화 화면 선택지 버튼 추가"
git push -u origin 이름/기능          # GitHub에서 PR 만들기 (템플릿 체크)
```
- 다른 컴퓨터의 PR이 머지되면 내 브랜치에 받아 온다: `git pull origin main`

## 5. Claude Code·GPT로 같이 작업할 때

- Claude Code는 `CLAUDE.md`를, GPT 계열 도구는 `AGENTS.md`를 읽고 09로 간다. 처음 시작할 때 AI가 역할을 묻는다
- AI에게도 2장을 따르게 한다. 내 담당이 아닌 걸 정하려 하면 멈추고 사람에게 묻게 한다
- 한 컴퓨터에서 여러 작업을 병렬로 할 땐 git worktree 사용
  ```bash
  git worktree add ../kokkiri-parent -b jaemo/parent
  ```
- AI한테 맡긴 결과도 **본인이 실행해 보고** PR 올린다
