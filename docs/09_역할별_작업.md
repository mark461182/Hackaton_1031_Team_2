# 09 역할별 작업

이 저장소를 읽은 사람이나 AI(Claude, GPT)가 **자기 역할에서 바로 무엇을 하면 되는지** 적은 문서다. 역할과 폴더 담당의 기준은 [04 협업 규칙](04_협업_규칙.md) 1·3장, 범위는 [03 MVP 스펙](03_MVP_스펙.md) "만드는 것", 결정은 [05 결정 기록](05_결정_기록.md)이다. 코드를 쓰는 컴퓨터는 두 대다: 컴퓨터 1(건준), 컴퓨터 2(**04:00쯤까지 성준·재모, 넘긴 뒤 도하**). 성준·재모는 넘긴 뒤 코드를 고치지 않고, 도하는 넘겨받기 전까지 저장소 코드를 고치지 않는다. (11/1 작성, 넘김 반영)

## 0. 이 문서를 읽는 AI에게

1. 먼저 사용자에게 역할을 묻는다: **건준 / 성준·재모 / 도하**. 성준·재모나 도하면 넘김(04:00쯤) 전인지 뒤인지도 묻는다
2. 그 역할의 장에서 "먼저 할 일"을 위에서부터 한다. 04 3장의 그 컴퓨터 몫 폴더 밖은 고치지 않는다. 컴퓨터 2 몫은 넘김 전에는 성준·재모가, 뒤에는 도하가 고친다
3. 다른 컴퓨터와 맞닿는 곳은 1장 "합치는 약속"만 믿는다. 약속을 바꿔야 하면 멈추고 사람에게 말한다 (팀 채널)
4. 말투·대사·화면 세부 디자인·숫자 같은 걸 정해야 하면 04 2장으로 누구 몫인지 본다. 내 몫이 아니면 정하지 말고 묻는다
5. 05 "미정"(이름, 가격)은 임의로 채우지 않는다
6. 사용자는 개발 초보일 수 있다. 명령은 하나씩, 무엇을 하는지 한 줄 설명과 함께 준다. git은 04 4장 "초보용 세 줄"을 따른다

## 1. 합치는 약속 (컴퓨터 1 · 건준 ↔ 컴퓨터 2)

따로 만든 것을 합칠 때 부딪히지 않게 하는 약속이다. 이것만 지키면 각자 자기 폴더 안에서 무엇을 하든 된다.

1. **`src/lib/types.ts`가 유일한 약속이다** (건준, #8). 03 데이터 구조와 API 요청·응답 모양을 담는다. 바꿀 땐 팀 채널에 알린다
2. **API는 저장하지 않는다** (건준, LLM·TTS만). 필요한 맥락(대화 기록, 대기 중인 부모 질문)은 요청에 담아 받고, 결과(코끼리 답, 분류, 답장 카드·위험 알림·공유 제안 내용, 물었다/답했다 신호)를 돌려준다. 부모에게 무엇이 가는지는 API 한 곳에서 정한다
3. **저장은 `src/lib/store.ts` 한 곳이다** (컴퓨터 2). 화면은 Supabase를 직접 부르지 않고 store.ts 함수만 부른다. API 결과를 저장하는 것도 화면이 store.ts로 한다. Supabase가 아직이면 store.ts 안에서 브라우저 저장으로 먼저 돌리고 화면은 그대로 둔다. 서버에서 Supabase를 불러야 하면 컴퓨터 2가 `src/app/api/data/**`를 쓰고 건준에게 알린다. 음성 파일은 올리지 않는다
4. **API는 키가 없어도 같은 모양의 가짜 응답을 낸다** (#9). 진짜 LLM이 붙어 있어도 실패하면 가짜 응답으로 대체된다 (#12). 화면은 응답 모양만 믿는다
5. **코끼리 그림**: 도하가 그리고, `public/kokkiri/`에 `idle`(기본), `listening`(듣는 중), `thinking`(생각 중), `speaking`(말하는 중) 이름으로 넣는다. 넘김 전에 그림이 나오면 팀 채널로 넘기고 성준·재모가 넣는다. 없으면 `/kid`가 임시 자리를 보여 준다 (#14)
6. **디자인**: 색·글꼴·공용 컴포넌트는 `globals.css`와 `src/components/**`에 둔다. 넘김 전에는 성준·재모가 단순하게 두고, 넘긴 뒤 도하가 다듬는다. 화면은 공용 컴포넌트를 가져다 쓰고 화면 파일 안에 따로 만들지 않는다
7. **예시 가족**은 컴퓨터 2가 `src/data/**`에 둔다. 방문자마다 따로 만들어 심사위원끼리 섞이지 않게 한다
8. **두 폰 데모 모드** `/demo`는 `/kid`와 `/parent`를 그대로 나란히 띄운다. 그래서 각 화면은 폰 너비 한 칸에서 돌아가야 한다. 두 칸이 같은 예시 가족을 보게 하는 건 store.ts가 맡는다
9. **같이 쓰는 파일**: `package.json`·`package-lock.json`을 바꾸는 PR(예: Supabase)은 그것만 작게 따로 올리고 바로 머지한다. 충돌 나면 main을 받아 `npm install`로 lock을 다시 만든다. `.env.example`에는 키 이름만 넣는다 (값은 팀 채널)
10. **합치는 순서**: store.ts → `/kid` 저장 연결(`onTurn`, `pendingQuestion`) → `/parent` → `/demo`. 배포 주소의 `/demo`에서 부모 질문 → 아이 대화 → 답장 카드 → 위험 알림이 글자로 한 바퀴 도는 것이 목표다. 05:00 화면 고정 (04 6장)

## 3. 성준·재모 — 04:00쯤까지 만들기, 넘긴 뒤 점검·지원

### 3-1. 넘기기 전 (~04:00, 컴퓨터 2)

**읽을 것**: CLAUDE.md, 03 "만드는 것"·"화면"·"핵심 흐름"·"저장 함수"·"데모 체크", 이 문서 1장, `src/lib/types.ts`, `src/app/kid/KidChat.tsx`

**먼저 할 일** (03의 "꼭 동작" 줄부터, 되는 데까지)
1. `src/lib/store.ts` (03 "저장 함수"): 예시 가족 만들기·불러오기(방문자마다 따로), 대화·답장 카드·위험 알림 저장, 대기 중인 부모 질문, 부모 피드(새로 생기면 바로 보이게). Supabase가 아직이면 브라우저 저장으로 먼저
2. `/kid`에 저장 연결: 대화 한 바퀴는 main에 있다(`KidChat.tsx`, 건준). 화면 코드는 그대로 두고 `onTurn(kidText, res)`로 한 턴씩 저장, `pendingQuestion`으로 대기 중인 부모 질문 넘기기
3. `/parent` 피드 (답장 카드·위험 알림·공유)와 `/parent/ask` (원래 질문·코끼리 버전 나란히)
4. 첫 화면 `/` (역할 선택, "예시 가족으로 체험하기")와 `/demo` 두 화면
5. 대화 마치기 → 코인. 최소 기준·횟수 숫자를 정해 03 "핵심 흐름" 코인 줄에 적는다
6. 시간이 남으면: 공유 [좋아]/[싫어], 3줄 일기와 달력, 정적 화면

**지킬 것**: 아이 화면에 "부모에게 전달된다"는 말을 넣지 않는다. 공유 제안 길만 예외 (CLAUDE.md). 분류·전달 규칙은 화면에서 바꾸지 않는다. 건준 폴더(`src/app/api/**`, `src/lib/llm`, `src/lib/voice`, `src/lib/types.ts`)는 고치지 않는다

### 3-2. 넘길 때 (04:00쯤)

되는 데까지 그대로 브랜치에 올린다. 빌드가 안 돼도 된다 (main에는 머지하지 않는다). 브랜치 이름을 팀 채널에 올리고, 어디까지 됐는지 한두 줄 적는다.
