# 09 역할별 작업

이 저장소를 읽은 사람이나 AI(Claude, GPT)가 **자기 역할에서 바로 무엇을 하면 되는지** 적은 문서다. 역할과 폴더 담당의 기준은 [04 협업 규칙](04_협업_규칙.md) 1·3장, 범위는 [03 MVP 스펙](03_MVP_스펙.md) "만드는 것", 결정은 [05 결정 기록](05_결정_기록.md)이다. 코드를 쓰는 컴퓨터는 두 대다: 컴퓨터 1(건준), 컴퓨터 2(성준·재모). 도하는 코드를 고치지 않는다. (11/1 작성)

## 0. 이 문서를 읽는 AI에게

1. 먼저 사용자에게 역할을 묻는다: **건준 / 성준·재모 / 도하**
2. 그 역할의 장에서 "먼저 할 일"을 위에서부터 한다. 04 3장의 그 컴퓨터 몫 폴더 밖은 고치지 않는다
3. 다른 컴퓨터와 맞닿는 곳은 1장 "합치는 약속"만 믿는다. 약속을 바꿔야 하면 멈추고 사람에게 말한다 (팀 채널)
4. 말투·대사·화면 세부 디자인·숫자 같은 걸 정해야 하면 04 2장으로 누구 몫인지 본다. 내 몫이 아니면 정하지 말고 묻는다
5. 05 "미정"(이름, 가격)은 임의로 채우지 않는다
6. 사용자는 개발 초보일 수 있다. 명령은 하나씩, 무엇을 하는지 한 줄 설명과 함께 준다. git은 04 4장 "초보용 세 줄"을 따른다

## 1. 합치는 약속 (컴퓨터 1 ↔ 컴퓨터 2)

따로 만든 것을 합칠 때 부딪히지 않게 하는 약속이다. 이것만 지키면 각자 자기 폴더 안에서 무엇을 하든 된다.

1. **`src/lib/types.ts`가 유일한 약속이다.** 건준이 가장 먼저 main에 올린다. 03 데이터 구조와 API 요청·응답 모양을 담는다. 나오기 전에는 03 데이터 구조로 임시 타입을 자기 폴더 안에만 두고, 나오면 바로 바꾼다. 바꿀 땐 팀 채널에 알린다
2. **API는 저장하지 않는다** (건준, LLM·TTS만). 필요한 맥락(대화 기록, 대기 중인 부모 질문)은 요청에 담아 받고, 결과(코끼리 답, 분류, 답장 카드·위험 알림·공유 제안 내용, 물었다/답했다 신호)를 돌려준다. 부모에게 무엇이 가는지는 API 한 곳에서 정한다
3. **저장은 `src/lib/store.ts` 한 곳이다** (성준·재모). 화면은 Supabase를 직접 부르지 않고 store.ts 함수만 부른다. API 결과를 저장하는 것도 화면이 store.ts로 한다. 서버에서 Supabase를 불러야 하면 성준·재모가 `src/app/api/data/**`를 쓰고 건준에게 알린다. 음성 파일은 올리지 않는다
4. **가짜 응답이 먼저다.** 건준은 키가 없어도 같은 모양으로 돌아가는 가짜 응답을 먼저 낸다. 성준·재모는 그걸로 화면을 먼저 만들고, 진짜 LLM이 붙어도 화면은 고치지 않는다
5. **코끼리 그림**: 도하가 상태별 그림을 팀 채널로 넘기고, 성준·재모가 `public/kokkiri/`에 `idle`(기본), `listening`(듣는 중), `thinking`(생각 중), `speaking`(말하는 중) 이름으로 넣는다. 오기 전에는 임시 그림을 같은 이름으로 쓴다
6. **디자인**: 도하가 디자인 가이드(색·글꼴·버튼 느낌)를 팀 채널로 넘기고, 성준·재모가 `globals.css`와 `src/components/**`에 옮긴다. 화면은 공용 컴포넌트를 가져다 쓰고 화면 파일 안에 따로 만들지 않는다
7. **예시 가족**은 성준·재모가 `src/data/**`에 둔다. 방문자마다 따로 만들어 심사위원끼리 섞이지 않게 한다
8. **두 폰 데모 모드** `/demo`는 `/kid`와 `/parent`를 그대로 나란히 띄운다. 그래서 각 화면은 폰 너비 한 칸에서 돌아가야 한다. 두 칸이 같은 예시 가족을 보게 하는 건 store.ts가 맡는다
9. **같이 쓰는 파일**: `package.json`·`package-lock.json`을 바꾸는 PR(예: Bedrock SDK, Supabase)은 그것만 작게 따로 올리고 바로 머지한다. 충돌 나면 main을 받아 `npm install`로 lock을 다시 만든다. `.env.example`에는 키 이름만 넣는다 (값은 팀 채널)
10. **합치는 순서**: types.ts → 가짜 API와 store.ts → 화면 → 진짜 LLM. 02:30에 배포 주소의 `/demo`에서 부모 질문 → 아이 대화 → 답장 카드 → 위험 알림이 글자로 한 바퀴 돌아야 한다. 03:00 기능 동결 (04 6장)

## 2. 건준 — 코끼리 머리와 목소리 (컴퓨터 1)

**읽을 것**: CLAUDE.md, [08 대화 원칙](08_대화_원칙.md), 03 "핵심 흐름"·"API"·"LLM 프롬프트 요구사항"·"음성", 이 문서 1장

**먼저 할 일**
1. 배포 주소 확인 (Vercel, 타입캐스트 환경변수). 주소를 팀 채널에 올린다
2. `src/lib/types.ts`를 만들어 main에 PR (1장 1번). 성준·재모가 이걸 기다린다
3. `/api/kid/chat`, `/api/parent/ask`를 가짜 응답으로 먼저 (1장 4번)
4. AWS Bedrock 연결 → 진짜 프롬프트. 03 "분류 기준"의 규칙을 넣는다: 위험 알림에 아이 말 1~2문장, 위험과 답장 카드가 겹치면 위험 알림 하나, 가족이 당사자면 알림 없음, "말하지 마"·[싫어] 내용은 부모 쪽에 안 씀, 대기 질문은 몇 턴 안에 꼭 묻고 신호를 남김
5. `/api/kid/done` (3줄 일기, "말하지 마"·[싫어] 내용 제외)
6. 03 "데모 체크"의 입력 문장으로 돌려 보고, 잘 되는 시연 문장을 도하에게 넘긴다

**스스로 정하는 것**: 04 2장 건준 줄 (말투·대사·대화 흐름, 묻는 시점과 말, 답장 카드 범위, 코치 메모, 응답 필드 이름, 모델)

**넘겨줄 것**: types.ts·가짜 API → 성준·재모 / 배포 주소 → 전원 / 시연 문장 → 도하

**하지 않는 것**: 화면·저장 코드, Supabase 직접 다루기

**다 됐다는 기준**: 03 데모 체크 [꼭] 중 대화·분류·답장 카드·위험·가족·말하지 마 줄이 배포 주소에서 통과

## 3. 성준·재모 — 앱 전부 (컴퓨터 2)

**읽을 것**: CLAUDE.md, 03 "만드는 것"·"화면"·"핵심 흐름"·"저장 함수"·"데모 체크", 이 문서 1장

**먼저 할 일** (03의 "꼭 동작" 줄부터)
1. Supabase 프로젝트와 `src/lib/store.ts` (03 "저장 함수"): 예시 가족 만들기·불러오기(방문자마다 따로), 대화·답장 카드·위험 알림 저장, 대기 중인 부모 질문, 부모 피드(새로 생기면 바로 보이게). Supabase가 늦어지면 store.ts 안에서 먼저 브라우저 메모리로 돌리고, 화면은 그대로 둔 채 나중에 바꾼다
2. `/kid`: 꾹 누르고 말하기(`src/lib/voice` 그대로), 받아쓴 글자 확인, 선택지, 글자 입력, 생각 중, 읽어 주기
3. `/parent` 피드 (답장 카드·위험 알림·공유)와 `/parent/ask` (원래 질문·코끼리 버전 나란히)
4. 첫 화면 `/` (역할 선택, "예시 가족으로 체험하기")와 `/demo` 두 화면
5. 대화 마치기 → 코인. 최소 기준·횟수 숫자를 정해 03 "핵심 흐름" 코인 줄에 적고, store.ts가 그 숫자로 지킨다
6. 도하의 그림·디자인 가이드가 오면 넣는다 (1장 5·6번)
7. 되면: 공유 [좋아]/[싫어], 3줄 일기와 `/kid/calendar`·`/parent/calendar`, 사진 올리기
8. 정적 화면: `/kid/coins`, `/parent/charge`, `/parent/report`, `/parent/book`, 예시 가족 데이터 (`src/data/**`)

**둘이 일하는 법**: 한 명은 키보드를 잡고 AI에게 시키고, 한 명은 배포 주소에서 03 데모 체크를 눌러 보며 안 되는 걸 적는다. 30분마다 바꾼다. AI 세션 둘을 동시에 돌리려면 worktree 둘로 화면 쪽과 저장·데모 쪽을 나눈다 (04 5장)

**지킬 것**: 아이 화면에 "부모에게 전달된다"는 말을 넣지 않는다. 공유 제안 길만 예외 (CLAUDE.md)

**스스로 정하는 것**: 04 2장 성준·재모 줄 (화면 배치·동작, 가이드를 화면에 옮기는 방법, 저장 구조, 예시 가족 내용, 정적 화면 모양, 코인 숫자)

**넘겨줄 것**: 02:30 체크포인트 한 바퀴 → 전원 / 배포 주소의 화면 → 도하 (점검용)

**하지 않는 것**: 분류·전달 규칙을 화면에서 바꾸기, 건준 폴더(`src/app/api/**`, `src/lib/llm`, `src/lib/voice`) 고치기 (1장 3번 예외 빼고)

**다 됐다는 기준**: 03 데모 체크 [꼭] 중 화면 줄과 [되면]·[정적] 중 고른 줄이 배포 주소에서 통과

## 4. 도하 — 코끼리 그림·디자인 가이드·발표 (코드 없음)

**먼저 할 일**
1. 서비스·코끼리 이름 (05 #10) → 팀 채널에 올리고 05에 덧붙인다
2. 디자인 가이드 한 장 (색·글꼴·버튼 느낌) → 팀 채널. 성준·재모가 화면에 옮긴다. 빠를수록 좋다
3. 코끼리 상태 그림 4장 (1장 5번) → 팀 채널. 금쪽이 스피커 코끼리와 닮지 않게 (CLAUDE.md)
4. 가격 숫자와 출처 (05 #14)
5. 배포 주소에서 03 데모 체크를 눌러 보고, 고칠 점을 성준·재모에게 메모로
6. 발표 자료 10장 안팎, 60초 데모 영상 (05:00 화면 고정 뒤 촬영). 발표·Remotion 파일은 앱 저장소 밖에 둔다
7. Q&A 답 확정 (01 4장 "[발표 담당이 확정]")

**스스로 정하는 것**: 04 2장 도하 줄 (코끼리 생김새·상태, 디자인 가이드, 이름, 가격 숫자, 발표)

**넘겨줄 것**: 이름 → 전원 / 디자인 가이드·코끼리 그림 → 성준·재모 / 고칠 점 메모 → 성준·재모

**받을 것**: 배포 주소·시연 문장(건준), 02:30 한 바퀴(성준·재모)
