# 09 역할별 작업

이 저장소를 읽은 사람이나 AI(Claude, GPT)가 **자기 역할에서 바로 무엇을 하면 되는지** 적은 문서다. 역할과 폴더 담당의 기준은 [04 협업 규칙](04_협업_규칙.md) 1·3장, 범위는 [03 MVP 스펙](03_MVP_스펙.md) "만드는 것", 결정은 [05 결정 기록](05_결정_기록.md)이다. 코드를 쓰는 컴퓨터는 두 대다: 컴퓨터 1(건준), 컴퓨터 2(**03:15부터 도하**, 그전엔 성준·재모). 성준·재모는 03:15부터 코드를 고치지 않는다. (11/1 작성, 03:15 넘김 반영)

## 0. 이 문서를 읽는 AI에게

1. 먼저 사용자에게 역할을 묻는다: **건준 / 도하 / 성준·재모**
2. 그 역할의 장에서 "먼저 할 일"을 위에서부터 한다. 04 3장의 그 컴퓨터 몫 폴더 밖은 고치지 않는다. 성준·재모는 코드를 고치지 않는다
3. 다른 컴퓨터와 맞닿는 곳은 1장 "합치는 약속"만 믿는다. 약속을 바꿔야 하면 멈추고 사람에게 말한다 (팀 채널)
4. 말투·대사·화면 세부 디자인·숫자 같은 걸 정해야 하면 04 2장으로 누구 몫인지 본다. 내 몫이 아니면 정하지 말고 묻는다
5. 05 "미정"(이름, 가격)은 임의로 채우지 않는다
6. 사용자는 개발 초보일 수 있다. 명령은 하나씩, 무엇을 하는지 한 줄 설명과 함께 준다. git은 04 4장 "초보용 세 줄"을 따른다

## 1. 합치는 약속 (컴퓨터 1 · 건준 ↔ 컴퓨터 2 · 도하)

따로 만든 것을 합칠 때 부딪히지 않게 하는 약속이다. 이것만 지키면 각자 자기 폴더 안에서 무엇을 하든 된다.

1. **`src/lib/types.ts`가 유일한 약속이다** (건준, #8). 03 데이터 구조와 API 요청·응답 모양을 담는다. 바꿀 땐 팀 채널에 알린다
2. **API는 저장하지 않는다** (건준, LLM·TTS만). 필요한 맥락(대화 기록, 대기 중인 부모 질문)은 요청에 담아 받고, 결과(코끼리 답, 분류, 답장 카드·위험 알림·공유 제안 내용, 물었다/답했다 신호)를 돌려준다. 부모에게 무엇이 가는지는 API 한 곳에서 정한다
3. **저장은 `src/lib/store.ts` 한 곳이다** (도하). 화면은 Supabase를 직접 부르지 않고 store.ts 함수만 부른다. API 결과를 저장하는 것도 화면이 store.ts로 한다. Supabase가 아직이면 store.ts 안에서 브라우저 저장으로 먼저 돌리고 화면은 그대로 둔다. 서버에서 Supabase를 불러야 하면 도하가 `src/app/api/data/**`를 쓰고 건준에게 알린다. 음성 파일은 올리지 않는다
4. **API는 키가 없어도 같은 모양의 가짜 응답을 낸다** (#9). 진짜 LLM이 붙어 있어도 실패하면 가짜 응답으로 대체된다 (#12). 화면은 응답 모양만 믿는다
5. **코끼리 그림**: 도하가 `public/kokkiri/`에 `idle`(기본), `listening`(듣는 중), `thinking`(생각 중), `speaking`(말하는 중) 이름으로 넣는다. 없으면 `/kid`가 임시 자리를 보여 준다 (#14)
6. **디자인**: 도하가 `globals.css`와 `src/components/**`에 넣는다. 화면은 공용 컴포넌트를 가져다 쓰고 화면 파일 안에 따로 만들지 않는다
7. **예시 가족**은 도하가 `src/data/**`에 둔다. 내용 초안은 성준·재모가 글로 넘긴다. 방문자마다 따로 만들어 심사위원끼리 섞이지 않게 한다
8. **두 폰 데모 모드** `/demo`는 `/kid`와 `/parent`를 그대로 나란히 띄운다. 그래서 각 화면은 폰 너비 한 칸에서 돌아가야 한다. 두 칸이 같은 예시 가족을 보게 하는 건 store.ts가 맡는다
9. **같이 쓰는 파일**: `package.json`·`package-lock.json`을 바꾸는 PR(예: Supabase)은 그것만 작게 따로 올리고 바로 머지한다. 충돌 나면 main을 받아 `npm install`로 lock을 다시 만든다. `.env.example`에는 키 이름만 넣는다 (값은 팀 채널)
10. **합치는 순서**: store.ts → `/kid` 저장 연결(`onTurn`, `pendingQuestion`) → `/parent` → `/demo`. 04:15에 배포 주소의 `/demo`에서 부모 질문 → 아이 대화 → 답장 카드 → 위험 알림이 글자로 한 바퀴 돌아야 한다. 05:00 화면 고정 (04 6장)

**다 됐다는 기준**: 03 데모 체크 [꼭] 중 대화·분류·답장 카드·위험·가족·말하지 마 줄이 배포 주소에서 통과

## 3. 도하 — 화면·저장·디자인 + 코끼리 그림·발표 (컴퓨터 2, 03:15부터)

**읽을 것**: CLAUDE.md, 03 "만드는 것"·"화면"·"핵심 흐름"·"저장 함수"·"데모 체크", 이 문서 1장, `src/lib/types.ts`, `src/app/kid/KidChat.tsx`

**먼저 할 일** (03의 "꼭 동작" 줄부터)
1. 넘겨받기: 성준·재모가 올린 브랜치에서 부모 화면·저장·쓸 만한 조각을 가져온다. `/kid`는 main에 있는 것(#14·#15)을 기준으로 하고, 같은 파일이 겹치면 main 쪽을 남긴다
2. `src/lib/store.ts` (03 "저장 함수"): 예시 가족 만들기·불러오기(방문자마다 따로), 대화·답장 카드·위험 알림 저장, 대기 중인 부모 질문, 부모 피드(새로 생기면 바로 보이게). Supabase가 아직이면 브라우저 저장으로 먼저
3. `/kid`에 저장 연결: `onTurn(kidText, res)`로 한 턴씩 저장, `pendingQuestion`으로 대기 중인 부모 질문 넘기기
4. `/parent` 피드 (답장 카드·위험 알림·공유)와 `/parent/ask` (원래 질문·코끼리 버전 나란히)
5. 첫 화면 `/` (역할 선택, "예시 가족으로 체험하기")와 `/demo` 두 화면
6. 대화 마치기 → 코인. 최소 기준·횟수 숫자를 정해 03 "핵심 흐름" 코인 줄에 적고, store.ts가 그 숫자로 지킨다
7. 디자인: 색·글꼴·공용 컴포넌트(`globals.css`, `src/components/**`), 코끼리 상태 그림(`public/kokkiri/`). 금쪽이 스피커 코끼리와 닮지 않게 (CLAUDE.md)
8. 되면: 공유 [좋아]/[싫어], 3줄 일기와 달력, 사진. 정적 화면: `/kid/coins`, `/parent/charge`, `/parent/report`, `/parent/book`
9. 05:00 화면 고정 뒤: 60초 데모 영상, 발표 10장 안팎, Q&A 답(01 4장), 이름·가격(05 #10·#14). 발표·Remotion 파일은 앱 저장소 밖에 둔다

**지킬 것**: 아이 화면에 "부모에게 전달된다"는 말을 넣지 않는다. 공유 제안 길만 예외 (CLAUDE.md). 분류·전달 규칙은 화면에서 바꾸지 않는다. 건준 폴더(`src/app/api/**`, `src/lib/llm`, `src/lib/voice`, `src/lib/types.ts`)는 고치지 않는다 (1장 3번 예외 빼고)

**스스로 정하는 것**: 04 2장 도하 줄 (화면 배치·동작·디자인, 저장 구조, 예시 가족 데이터, 정적 화면 모양, 코인 숫자, 코끼리 생김새·상태, 이름, 가격, 발표)

**넘겨줄 것**: 04:15 체크포인트 한 바퀴 → 전원 / 배포 주소의 화면 → 성준·재모 (점검용)

**받을 것**: 성준·재모 브랜치(화면 작업), 점검 메모와 예시 가족 내용 초안(성준·재모), 시연 문장(건준)

**다 됐다는 기준**: 03 데모 체크 [꼭] 중 화면 줄과 [되면]·[정적] 중 고른 줄이 배포 주소에서 통과

## 4. 성준·재모 — 넘기기·점검·발표 지원 (03:15부터 코드 없음)

**먼저 할 일**
1. 지금까지 만든 화면 작업을 그대로 브랜치에 올린다 (빌드가 안 돼도 된다. main에는 머지하지 않는다). 브랜치 이름을 팀 채널에 올린다. 그 뒤 저장소 코드를 고치지 않는다
   ```bash
   git switch -c sungjun/screens
   git add -A && git commit -m "아이·부모 화면 중간 저장 (도하에게 넘김)"
   git push -u origin sungjun/screens
   ```
2. 예시 가족 내용 초안을 글로 써서 도하에게: 아이 이름·나이, 지난 며칠 대화 몇 줄, 부모가 맡길 질문 몇 개, 3줄 일기 몇 개
3. 배포 주소에서 03 데모 체크를 눌러 보고, 안 되는 것을 도하·건준에게 적어 준다 (어느 화면에서, 무엇을 눌렀더니, 무엇이 나왔는지)
4. 05:00부터 영상 녹화 손(부모·아이 화면 조작), 발표 리허설과 Q&A 연습 상대

**하지 않는 것**: 저장소 코드 수정

**받을 것**: 배포 주소(건준), 점검할 화면(도하)
