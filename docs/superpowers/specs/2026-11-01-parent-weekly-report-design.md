# 부모 주간 리포트 설계

## 의도

부모가 날짜별 기록을 하나씩 열어 보지 않아도 이번 주 아이의 일상을 빠르게 이해하고, 다음 대화를 시작할 질문을 바로 고를 수 있게 한다.

## 목표

- `/parent/calendar` 상단에 `이번 주 한눈에` 미리보기 카드를 둔다.
- 미리보기에서 `/parent/report` 전체 리포트로 이동한다.
- 전체 화면에는 이번 주 기간, 요약, 기억할 이야기, 다음 주 추천 질문을 표시한다.
- `docs/03_MVP_스펙.md`의 정적 화면 범위에 맞춰 예시 데이터만 사용한다.
- 모바일 한 칸과 `/demo` 안의 폰 너비에서도 읽기 쉽게 유지한다.

## 하지 않는 것

- 리포트 생성 API, LLM 호출, Supabase 저장을 추가하지 않는다.
- `src/lib/types.ts`, `src/app/api/**`, `src/lib/llm/**`, `src/lib/voice/**`를 수정하지 않는다.
- 진단·판정 표현, 서비스 이름, 가격을 새로 정하지 않는다.
- 아이가 부모에게 알리지 말라고 한 내용이나 거절한 공유 내용을 예시 리포트에 넣지 않는다.

## 검토한 방식

1. **달력 미리보기 + 별도 전체 화면 — 선택**
   - 달력에서 자연스럽게 발견할 수 있고, 긴 리포트는 `/parent/report`에서 편하게 읽을 수 있다.
   - MVP 화면 목록의 `/parent/report` 경로를 그대로 충족한다.
2. **별도 화면만 추가**
   - 구현은 가장 작지만 부모가 리포트를 발견하기 어렵다.
3. **달력 안에 전체 리포트 표시**
   - 이동은 줄지만 달력 화면이 길어지고 별도 경로 요구와 맞지 않는다.

## 화면 구조

### `/parent/calendar`

- 월 이동 영역 위에 이번 주 기간과 한 문장 요약을 담은 연녹색 카드를 배치한다.
- 카드 전체를 링크로 사용하고 `주간 리포트 보기` 문구로 이동 목적을 명확히 한다.
- 로딩·오류 상태에서는 기존 달력 동작을 유지한다.

### `/parent/report`

- 상단: 부모 달력으로 돌아가기, `주간 리포트` 제목, 이번 주 기간.
- 요약: 아이가 이번 주 자주 이야기한 활동과 긍정적인 변화를 단정하지 않는 표현으로 정리한다.
- 기억할 이야기: 예시 3줄 일기에서 부모가 대화를 이어 갈 수 있는 장면 2개를 보여 준다.
- 다음 주 추천 질문: 열린 질문 3개를 카드로 제공한다. 질문을 맡기는 실제 동작은 만들지 않고 `/parent/ask`로 이동한다.
- 하단: 기존 `ParentBottomNav`의 `기록` 탭을 활성화한다.

## 데이터와 코드 경계

- 정적 예시 리포트는 `src/data/parent-report.ts`에 둔다.
- 날짜 계산과 화면 표시용 모델은 `src/app/parent/report/report-model.ts`에 둔다.
- 달력과 리포트 화면은 예시 데이터를 읽기만 하며 Supabase나 API를 직접 호출하지 않는다.
- 가족 이름과 아이 이름은 기존 `store.getOrCreateDemoFamily()`로 불러온다.

## 검증

- 모델 테스트로 주 시작일·종료일, 기간 문구, 가족별 예시 데이터 생성을 검증한다.
- `/parent/calendar`에서 `/parent/report` 링크가 보이는지 확인한다.
- `/parent/report`에 요약과 다음 주 추천 질문 3개가 표시되는지 확인한다.
- 전체 테스트, `npm run lint`, `npm run build`를 실행한다.
