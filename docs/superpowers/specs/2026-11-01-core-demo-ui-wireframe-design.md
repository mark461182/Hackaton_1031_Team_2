# 코끼리 핵심 데모 UI 와이어프레임 설계

## 의도

초등학교 1~3학년 아이가 코끼리 친구 Elly와 말로 대화하고, 부모는 질문을 맡기고 답장 카드와 위험 알림을 확인하는 핵심 흐름을 한눈에 이해할 수 있는 모바일 웹 UI를 만든다. 첫 Figma 작업은 전체 기능을 넓게 펼치기보다 해커톤 심사에서 반드시 보여 줄 흐름을 먼저 연결하고, 팀이 화면을 보며 빠르게 수정할 수 있는 와이어프레임을 제공하는 데 목적이 있다.

## 목표

- 역할 선택 → 아이 대화 → 부모 피드·질문 → 두 폰 데모가 끊기지 않게 보인다.
- 아이 화면의 중심은 채팅 목록이 아니라 상태가 바뀌는 Elly 캐릭터와 음성 행동이다.
- 기존 `/kid`의 글자 입력, 음성 입력, 선택지, 오류 복구 동작은 모두 유지한다.
- 부모 화면은 답장 카드, 위험 알림, 공유된 이야기를 우선순위와 성격에 맞게 구분한다.
- 390px 모바일을 기준으로 하고, `/demo`에서는 같은 모바일 화면 두 개를 데스크톱에 나란히 둔다.
- 요청된 색상과 두 글꼴을 일관된 디자인 토큰과 컴포넌트로 정리한다.

## 비목표

- 이번 1차 와이어프레임에서 달력, 코인 교환, 충전, 리포트, 스토리북의 상세 화면을 만들지 않는다.
- 코끼리 대사, 분류·전달 규칙, API 응답 모양을 새로 정하지 않는다.
- 실제 결제, 회원가입, 푸시 알림을 설계하지 않는다.
- 제품 코드를 수정하거나 새 패키지를 추가하지 않는다.

## 고정 제약

- 이 작업의 저장소 역할은 `성준·재모`이며, 화면·컴포넌트·디자인 적용 범위 안에서 결정한다.
- 아이 화면에 부모 질문이라는 사실이나 답이 부모에게 전달된다는 사실을 쓰지 않는다.
- 공유 제안에서 아이에게 함께 말할지 묻는 흐름만 예외다.
- “비밀로 해 줄게”, 진단·판정·학폭 방지 같은 표현을 쓰지 않는다.
- 아이 화면은 음성이 기본이며 글자와 선택지는 항상 대체 수단으로 남긴다.
- 화면 문구는 한국어로 쓴다.
- Elly 상태 이미지는 `src/lib/elly/**`의 기존 자산만 사용한다.
- 성준·재모 담당 폴더 밖의 제품 코드는 수정하지 않는다.

## 검토한 접근

### 핵심 데모 흐름 우선 — 선택

역할 선택, 아이 대화 상태, 부모 피드·질문, `/demo`를 먼저 만든다. 심사 동선과 현재 구현 범위에 직접 맞고, 팀이 작은 화면 묶음을 보며 빠르게 수정할 수 있다.

### 전체 화면 지도

스펙의 모든 경로를 동시에 와이어프레임으로 만든다. 전체 구조는 빨리 보이지만 아직 구현되지 않은 정적 화면까지 결정해야 해서 핵심 대화 경험의 완성도가 낮아질 수 있다.

### 아이 경험 우선

Elly와 음성 대화만 깊게 설계한다. 캐릭터 경험은 강해지지만 부모 질문 → 아이 답 → 부모 카드라는 제품의 차별적인 데모 흐름을 검토하기 늦어진다.

## 디자인 방향

`design-taste-frontend`가 제안한 앱 스타일 중 개인·가족 홈에 맞는 `editorial-greeting`을 바탕으로 한다. 다만 데스크톱 업무용 사이드바는 이 모바일 앱에 맞지 않으므로 사용하지 않고, “가족 이름과 오늘의 한 가지 사실을 먼저 보여 주고, 색보다 정보와 캐릭터가 앞서는 구조”만 채택한다.

이 제품만의 시각 장치는 Elly의 상태 변화다. 아이 화면에서는 큰 캐릭터가 현재 상태를 설명하고, 부모 화면에서는 `준우네`와 오늘의 새 소식을 첫 줄에서 알려 준다. 장식용 아이콘, 그라디언트, 유리 효과, 고정 카드 그리드를 사용하지 않는다.

## 디자인 토큰

### 색상

- 메인 배경 `Warm Ivory` — `#F7F4EC`
- 브랜드·주요 행동 `Muted Sage` — `#728F7A`
- 주요 버튼 `Deep Sage` — `#4F6F59` (흰 글자 대비 5.60:1)
- 보조 배경·선택 상태 `Light Sage` — `#DCE8D8`
- 감정 포인트 `Soft Peach` — `#E9B89A`
- 기본 텍스트 `Charcoal` — `#383D37`
- 카드 기본 — `#FFFFFF`
- 카드 보조 — 배경보다 한 단계 밝은 크림색
- 오류·위험 — 브랜드 색을 재활용하지 않고 접근 가능한 별도 빨강을 소량 사용한다.

`Muted Sage`는 현재 상태와 핵심 데이터에 쓰고, 주요 버튼은 흰 글자 대비를 확보한 `Deep Sage`를 쓴다. `Soft Peach`는 감정적 강조나 아이 화면의 보조 선택 한 곳에만 쓰며 배경 전체를 채우지 않는다.

### 글꼴

- 본문, 입력, 부모 정보: `Pretendard`
- 제목, 주요 버튼, 아이에게 보이는 친근한 짧은 문구: `NanumSquareRound`
- 한 화면에서 두 글꼴의 역할을 섞지 않는다.
- 제공된 Pretendard 웹폰트는 100 굵기만 포함하므로 실제 구현에서는 같은 패밀리의 400·600 굵기를 추가해 본문 가독성을 확보한다.

### 형태와 간격

- 모바일 바깥 여백 20px, 주요 세로 간격 16px와 24px
- 카드 라운드 20px, 작은 패널 16px, 입력과 버튼 16px
- 주요 버튼 높이 최소 52px, 음성 버튼 최소 64px
- 고정 카드에는 그림자를 쓰지 않고 배경 톤 차이로 구분한다.
- 본문 15~16px, 보조 문구 13px 이상, 화면 제목 22~28px

## 화면 구조

### 역할 선택 `/`

화면의 질문은 “누가 체험을 시작하는가?”다.

- 상단: 서비스 이름과 한 문장 설명
- 중앙: `elephant_greet.webp`를 40~45% 높이로 크게 배치
- 하단: `아이로 시작하기`를 진한 세이지 버튼으로, `부모로 시작하기`를 Light Sage 보조 버튼으로 배치
- `예시 가족으로 체험하기`를 별도 텍스트 행동으로 제공
- `예시 가족으로 체험하기`는 예시 가족을 초기화한 뒤 `/demo`로 이동한다.
- 시스템 다크 모드와 무관하게 Warm Ivory 배경을 유지

### 아이 시작 `/kid` — 시작 전

화면의 질문은 “지금 Elly와 어떻게 이야기하는가?”다.

- 48px 상단 바: 뒤로가기, `Elly`, 코인 또는 종료 행동을 위한 자리
- 중앙 캐릭터 스테이지: `elephant_greet.gif`, 상태 문구, 최신 Elly 문장
- 하단 고정 행동: `이야기 시작` 버튼 하나
- 기존 원형 `elly` 문자 아바타는 제거

### 아이 대화 `/kid` — 듣기·생각·말하기

- 화면 중앙 42~48%는 상태 캐릭터 스테이지로 유지한다.
- 최신 한 쌍의 대화만 큰 말풍선으로 보여 주고, 이전 대화는 `지난 이야기 보기` 바텀시트에서 확인한다.
- 듣는 중에는 음성 버튼을 누른 상태와 실시간 받아쓴 글자를 함께 보여 준다.
- 손을 떼면 받아쓴 글자 확인 카드가 나타나고 `맞아`와 `다시 말하기`를 제공한다.
- 선택지는 가로 스크롤 칩이 아니라 2열 또는 전체 폭의 44px 이상 버튼으로 배치한다.
- 글자 입력은 `키보드로 말하기`를 누르면 펼쳐지는 보조 입력으로 둔다.
- 하단 음성 버튼은 엄지로 누르기 쉬운 전체 폭 64px 버튼이며 상태에 따라 문구와 색만 바뀐다.

### 부모 홈 `/parent`

화면의 질문은 “오늘 아이에게서 새로 온 중요한 소식은 무엇인가?”다.

- 첫 줄: `준우네에 새 소식이 있어요`와 새 항목 수
- 주요 행동: `아이에게 질문 맡기기`
- 피드 순서: 위험 알림 → 질문 답장 카드 → 공유된 이야기
- 위험 알림은 Soft Peach가 아닌 접근 가능한 옅은 빨강 표면을 사용하고, 아이 말 원문·상황 요약·대화 가이드를 한 카드 안에서 계층화한다.
- 답장 카드는 질문, 아이 답 원문, 코끼리 요약·메모 순서다.
- 공유된 이야기는 상태 표시를 최소화하고 일반 피드 톤으로 둔다.
- 하단 내비게이션은 4개 이하의 실제 목적지로 제한하며 1차 와이어프레임에서는 `홈`, `질문`, `기록`, `더보기` 자리만 잡는다.

### 부모 질문 `/parent/ask`

화면의 질문은 “부모의 걱정을 아이가 답하기 쉬운 질문으로 맡길 수 있는가?”다.

- 원래 질문 입력을 화면 첫 요소로 둔다.
- 변환 후에는 `내 질문`과 `Elly가 물어볼 말`을 세로로 비교한다.
- `이 질문 맡기기`가 유일한 주요 버튼이다.
- 질문이 이미 하나 대기 중이면 새 입력 대신 현재 질문과 대기 상태를 보여 준다.

### 두 폰 데모 `/demo`

- 데스크톱 Warm Ivory 바탕 위에 390px 폭의 부모·아이 화면을 24px 간격으로 나란히 둔다.
- 각 화면 위에 `부모 화면`, `아이 화면`이라는 데모용 외부 라벨을 둔다. 이 라벨은 실제 모바일 화면 내부에 포함하지 않는다.
- 두 폰은 동일한 예시 가족을 사용하고, 부모 질문 → 아이 대화 → 답장 카드·위험 알림의 변화가 동시에 보인다.
- 768px 이하에서는 두 화면을 세로로 쌓거나 각 화면으로 이동하는 탭을 제공한다.
- 768px 이하에서는 부모·아이 탭 전환을 사용해 한 번에 한 화면만 보여 준다. 세로로 두 폰을 길게 쌓지 않는다.

## 컴포넌트 구조

- `AppShell`: 모바일 폭, 안전 영역, Warm Ivory 배경
- `TopBar`: 뒤로가기, 화면 제목, 한 개의 보조 행동
- `EllyStage`: 상태별 이미지, 상태 문구, 최신 답변
- `HoldToTalkButton`: 준비·듣기·비활성 상태
- `TranscriptConfirm`: 받아쓰기 결과, 맞아·다시 말하기
- `ChoiceButtons`: 44px 이상 선택 버튼 묶음
- `FeedCard`: 답장·공유의 공통 구조
- `RiskAlertCard`: 위험 알림 전용 구조
- `QuestionComparison`: 원래 질문과 다듬은 질문
- `BottomNav`: 부모 화면 전용 4개 이하 목적지
- `DemoPhoneFrame`: `/demo`에서만 쓰는 외부 프레임

## 접근성·반응형

- 일반 글자 대비 4.5:1 이상, 큰 글자 3:1 이상을 지킨다.
- 모든 터치 대상은 최소 44×44px다.
- 상태를 색만으로 전달하지 않고 문구와 캐릭터 변화로 함께 알린다.
- `prefers-reduced-motion`에서는 GIF 대신 WebP를 사용한다.
- 키보드 포커스가 명확하며 글자 입력만으로 핵심 흐름을 끝낼 수 있다.
- 390px에서 가로 스크롤이 생기지 않는다.

## Figma 산출물

한 페이지 안에 다음 섹션을 만든다.

1. `Foundations`: 색상, 글꼴 역할, 간격, 라운드
2. `Components`: 버튼, 카드, 입력, Elly 상태, 내비게이션
3. `Kid Flow`: 시작 전, 듣기, 받아쓰기 확인, 생각, 말하기
4. `Parent Flow`: 홈 피드, 질문 입력, 질문 변환 결과
5. `Demo`: 두 폰 데스크톱 프레임

모든 화면은 390×844 기준이며, 상태 차이는 별도 화면을 복제하기보다 컴포넌트 variant로 만든다. 첫 검토에서는 회색 저충실도 박스가 아니라 요청된 색·폰트·실제 Elly 자산을 적용한 중간 충실도 와이어프레임을 보여 준다.

첫 산출물은 새 독립 Figma 파일의 정적 리뷰 보드다. 화면 간 이동과 상태 변화는 화살표와 짧은 주석으로 표시하고, 클릭 프로토타입 연결은 첫 디자인 피드백을 반영한 다음 라운드에서 추가한다.

`Components`에는 펼친 글자 입력, 선택지 버튼 묶음, 오류 복구, 지난 이야기 바텀시트, 부모 피드의 빈 상태·불러오는 상태·부분 오류, 대기 중인 질문 variant를 포함한다. 이 상태들은 1차 리뷰 보드에서 모든 화면을 복제하지 않고 대표 화면 옆에 variant로 배치한다.

## 제작자가 정할 수 있는 세부 사항

- Elly 캐릭터가 화면에서 차지하는 정확한 비율은 390px 캡처에서 말풍선과 음성 버튼이 첫 화면에 함께 보이는 범위에서 조정한다.
- `excited`와 `laugh`는 API 응답의 감정 분류가 없으므로 1차에서는 말하는 중 기본 변형을 하나만 사용하고, 다른 하나는 컴포넌트 예비 variant로 둔다.
