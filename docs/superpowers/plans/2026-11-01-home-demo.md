# Home And Two-Phone Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the elly role-selection home page and a desktop demo page that shows the existing parent and kid routes side by side.

**Architecture:** Keep navigation as ordinary Next.js links. Make `/demo` a client page that renders route metadata from a small pure model, embeds `/parent` and `/kid` without copying either screen, and resets example-family state only through `store.resetDemoFamily(getVisitorId())`.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, Tailwind CSS 4, Node built-in test runner.

**Spec:** `docs/03_MVP_스펙.md` sections “화면”, “저장 함수”, and “데모 체크”; `docs/09_역할별_작업.md` chapter 3 step 4.

## Global Constraints

- Do not modify `src/app/parent/**`, `src/app/api/**`, `src/lib/llm/**`, `src/lib/voice/**`, or `src/lib/types.ts`.
- `/demo` must embed the real `/parent` and `/kid` routes and must not duplicate their behavior.
- Screens must access persistence only through `src/lib/store.ts` functions.
- Use the service name and elephant name `elly`; do not invent elephant dialogue or pricing.
- Keep styling restrained until Doha supplies a design guide; do not add dependencies.

## Review Focus

- The three home actions must point to `/parent`, `/kid`, and `/demo` respectively.
- Demo panels must stay ordered parent then kid and retain accessible iframe titles.
- Reset must create a new example family and reload both embedded screens.
- A narrow viewport must remain usable by stacking the two panels rather than overflowing the page.
- Existing parent development must remain untouched and appear automatically inside the parent frame.
